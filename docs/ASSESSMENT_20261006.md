## 2. 问题清单（按性质分级）

### A. 信息论天花板（图纸里没有该信息——记账、不修）

1. **融合投影天花板**：剖面图纸路径 +3.81~4.23% 修不动——出图侧逐实体 Fuse 抹掉 CSG 交界线信号，是出图方式的选择（代码已就地注释）。
2. **bracket 臂区方块** x[96,162]×y[±25] z>27：能裁它的 B—B 棱柱缺可靠圆心对齐基准，「宁缺毋滥」门控跳过 sec_B/sec_C（正确行为）。
3. 信息论局限表其余条目：F 段顶 3mm 环、φ3.3 沉头锥、φ3.3/φ5.5 孔位 0.1mm 差、顶段角凸 16 边近似 −156、bracket 凸台 z[22,24] 两侧槽无信号。

### B. 新框架结构缺口（可修；README 与验收脚本已定名「下一抓手」）

【今日实测】OCC 表 9 靶子：

| 靶子 | 体积差 | 病灶 |
|------|--------|------|
| block_3view / plate_100x60 / flange_d80 / 法兰练习 | ±0.00% | ✅ 逐位吻合 |
| l_bracket | +227.27% | 基体 = 视图包围盒（真实外轮廓 L 形） |
| 图形练习 | +200.00% | 同上（台阶形） |
| bracket 三视图 | +130.35% | 真实外轮廓非矩形 |

| PF60K | −31.42%（17 特征、3 实体） | **回转体识别未做**（法兰盘按板类零件建） |

- 连带后果：SW 侧 3 个大靶子「按设计拒绝」（FeatureCut3 返回 None）——根因同上面两条 + `axial_at` 缺省 0。
- 缺口就两条：**轮廓环**（视图环 → 带圆弧 profile）+ **回转体识别**。修轮廓环不动发射器（验收脚本顶部已警示：不许为让表变绿去调发射器）。

### C. 旧管线残余

1. bracket 挂耳左半盒外多余 ~457（旧问题，修复前 483.3 → 456.9）。
2. **断裂视图完全没处理**（会当完整视图、直接读错尺寸）——新框架阶段 2 已有识别。
3. **局部剖/半剖无识别**（YZYX 的 C—C 即是）——YZYX 靠手工读图兜住；旧管线对此类图纸无解。
4. 入库产物 `motor_engineering.dxf` 与脚本产出脱节（跟踪版 380 实体 vs 现产出 1581）。

### D. 验证体系盲区（比精度更值得记的一条）

- 自动指标（体积 / bbox / 重合率）到 **99.5%+ 时局部可见缺陷仍然存在**——bracket 三缺陷、YZYX 四五处标记，均为用户目视发现，自动验证零命中。
- 无 3D 基准的靶子（YZYX）无法定量验收：只能投影评分 + 材料探针 + 用户目视，「验收必须实际生成模型」在无基准件上退化为「用户看一眼」。
- 即：**缺陷发现的入口目前仍是人眼**。渲染对照（`_render_dxf.py`）、截面叠加（`_dump_sections` / `_draw_sections`）、viewer（`_make_viewer.py`）工具都备着，但未制度化进每次修复流程。

### E. 工程债 / 产品化

1. **GUI 起不来**（【今日实测】两解释器仍无 PyQt6；第三环境历史记录亦无）；`src/` 侧 GUI 与算法全骨架；三套实现并存（旧管线 / `src/core` 骨架 / `src/rebuild`）。
2. `sw_driver.disconnect()` 收尾会关活动文档（用户要求先冻结不动）。
3. tag `v0.6.20-5-gb50663d` 落后 5 个提交，版本簿记待例行收口。
4. 根目录 215 个 `_*.py` 一次性脚本（YZYX 一族 70 个）——gitignored 但目录噪音大。
5. SW COM 工程图「只有一个视图」（91 天前记录，`CAD/temp_output/sw_create_drawing.py` 仍在，未复核）。
6. `src/core/reconstruction/` 已判定过时，待删除。

### F. 工作流弱点（自评）

1. **大复杂件（YZYX 级）自动管线读不动**，最终靠手工参数化收敛：15 版迭代 + 用户 4 轮读法闭环。可靠但慢，且不可复用（70 个脚本 = 单件专用）。
2. **制图约定误判**：把「细实线 = 被顶壁盖住的轮廓」读成「开口」（#1 争议三轮才收敛）；旧把 R8_5 当 R8。均靠反事实模型 / 材料探针 / 尺寸实体实测补证，纠错成本高。
3. **无基准件把验收压力转移给用户**：交付前给不出与有基准靶子等价的定量置信度。
4. **证据挖掘第一轮深度不够**：#1 直到第三轮才把图纸自带 DIMENSION 实体挖出来实测（「20」=20.0 /「3」=3.0 /「120」=120.0）——这本该是第一轮动作。

## 3. 优先级建议

1. **新框架轮廓环**（一刀解锁 l_bracket / 图形练习 / bracket 两个 GAP；已定名下一抓手）。
2. **回转体识别**（PF60K；顺带消解 SW 侧第一个「按设计拒绝」）。
3. **把 YZYX 教训沉淀成约定库**（局部剖 = 半边剖、细实线 = 被盖轮廓、DIMENSION 实体当尺寸证据、材料探针流程）——手工读图的知识前移进 `conventions/` 与工具链。
4. **验证制度化**：出图渲染对照 + 截面叠加列为每次修复的例行检查，把「用户目视」前移。
5. 工程债收口（tag / 产物刷新 / 脚本归档），低风险低成本。
6. GUI / 产品化留到最后（当前工作流不依赖）。
