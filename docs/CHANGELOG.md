## 新框架 src/rebuild/（v0.6.48，端面台阶裁决 + 近共面 Fuse 丢材料护栏，2026-10-26）

**症状**：v0.6.47 后 20180425 气缸前盖的孔都通了，A—A 截面仍有多料，其中 87%
落在基体两端：基体长度取「所有视图沿拉伸方向的跨度**并集**」，拉满 33
（69.83..102.83），而剖切面处的主材料只有 32（69.83..101.83）——右端多出的
1mm 是 Ø75×1 凸台，左端少掉的 1mm 是 Ø70×1 沉台。并集只保证**包住**零件，
不保证是主面；投影（圆柱提示只有半径与 span）读不出"哪一层是主面"。

**新模块 `features/face_steps.py`**（判据全在模块 docstring，接入点在
`recognizer.recognize` 的 `_section_materials` 之后、`cylinder_features` 之前）：
剖面 HATCH 材料沿剖面内另一轴逐列取沿拉伸轴的外包区间（`_rows`）→ 候选圆 =
剖切面内的已知轴线 × 半径（可见圆提示 / 直径标注，标注须过几何三条）→
在**圆边界内外 0.5mm 窄窗**找层位跃变（`_transition`，窗内须局部同高，
否则该圆不作证——小孔采样带跨过大圆台阶这类假阳性的出口）→ 采样值吸附到
HATCH 精确层位（`material.hatch_lines` + `_exact_levels`，图纸 6 位小数）→
**正跃变 = 沉台（HOLE 朝材料内）、负跃变 = 凸台（BOSS 朝外）**；圆外那个
精确层位就是主面，同一侧所有作证圆必须给出同一个主面。基体两端改写到主面，
每个作证圆发一条特征（`section:face_step_span`，Tier.PROJECTION）。

**实测（20180425 A—A）**：notes 三条 —— `端面台阶：基体深度由剖面材料裁决
69.83..102.83 → 69.83..101.83（…2 个圆作证）`、`端面沉台 Ø70.00×1.00 在
y=69.83（可见圆 r35）`、`端面凸台 Ø75.00×1.00 在 y=101.83（直径标注 75）`；
基体 `length` 33 → 32、`origin`/`placement` 同步（method=`section:face_step_span`）。体积 419,736.59 →
**407,323.90**；A—A 截面材料 99×172 网格：双方 7297 格不变，多料 521 →
**221**、少料 9 不变，**IoU 0.9323 → 0.9694**（33×40 粗网格多料 50 → 27）；

只看"全空"会把真材料切掉。修后 SolidClassifier 逐点复核：中心孔两端、
顶部竖孔、两条 Ø7 横孔右端全部 OUT（开口）。

**锥孔（`_taper_of` + `radius_top`）**：图纸顶部是 Ø11.6（锥底，深 15）→
Ø12.5（顶面）的锥孔，模型建成了 Ø11.83 直孔。两个叠加原因：①桶聚类的段

整数倍且按 (末格−首格) 计、系统性偏小最多一整格——真实锥度差 0.45 被量化
读成 0.30，卡在判据下。修法：回栅格沿轴重采样 + 两端**细化扫描**（步
GRID/6）量真实边界；判据 = 两端差 ∈ [0.35, 3.0] + 沿轴单调 + 无单步跳变
（台阶不是锥）。发射 `radius`（起始端）+ `radius_top`（远端），OCC 用
`MakeCone`（实测半角 1.807°、Ø11.57→Ø12.53）；SW 发射器明确拒绝锥孔
（FeatureCut3 拔模角未验证，不静默按直孔建）。

## 新框架 src/rebuild/（v0.6.46，剖面材料通道——A—A 内部阶梯孔/交叉孔，2026-10-23）

**症状**：v0.6.45 修好外形与剖视语义后，A—A 剖面材料对比仍有 1407 格"模型多料"：
中心阶梯孔（Ø36H7 − Ø42 环槽 − Ø36 − Ø40 环槽 − Ø36）、顶部 Ø10.7 螺纹底孔、
底部 Ø7 通道 + Ø7 竖直通道、z=148.68 的 Ø7 横孔——一条也没读出来。根因在通道
入口：`cylinder_features` 从**圆柱提示**进（正交视图里的圆），而剖切面穿过的
内部孔在任何正交视图里都不成圆。`_rebut_by_section` 只能把"已读成凸台的圆"
改判成孔，读不出没有圆的结构。

**新模块 `features/section_bore.py`**（判据全在模块 docstring，接入点是
`recognizer.recognize` 的 `cylinder_features` 之后）：

- 剖面 HATCH = 地面真值：沿视图内两轴栅格扫掠空腔 → 垂直方向恒定区间 →
  `(center, half)` 聚桶成段（`_candidates`）；
- **圆柱性证据**只有两种（否则只记账、不建，§3 原则二）：直径标注，或与已确认
  段同轴（`_prove` 链式扩散；同轴段沿用实测半宽）；
- 直径标注必须**几何成立**（`_dim_proof` 三条）：两点垂直间距 = 标注值、
  标注值 ≈ 2×段半宽、中点落在段轴上且在段跨度内；
- 剖切面位置 = **唯一候选**：从其它视图里的剖切线（`Role.AXIS` 点画线）读，
  零/多候选 ⇒ 整个剖面放弃（`_cut_plane_pos`）；
- 发射 HOLE（`axial_at` = 孔口、`through=False`）；同轴旧 HOLE 由
  `replace_coaxial` 摘掉（剖面材料是直接证据，压过投影猜测），
  `annotation:` 方法（孔标注绑定）与 BOSS 不动；`bind_axial_positions` 不改
  剖面段（`section:material_profile+*` 不在 span 平移表内）。

**三处踩坑（都写进代码注释）**：

1. **只按数值配标注会造假孔**：A—A 的 15 条尺寸全是 linear，其中「32」是通道
   深度、「15」是螺纹深、「17」/「33」是宽度——只按数值配对会让"Ø32 的孔"
   （实测半宽 16.20 的伪段）凭空冒出来。三点几何判据是必需的。
2. **Ø40 段被 WALL_FRAC=4/5 整个丢掉**：被 Ø7 横孔穿通的 3 个采样点外侧先穿过
   横腔、再往外是 1.1mm 薄壁岛（图上没 HATCH）⇒ 只有段两端两点能搜到材料；
   降为 **2/5**。零件外的空气带仍被 `MIN_SEG` + `MAX_HALF_FRAC` 挡住。
3. **「Ø48.78 环槽」是误读**：`_step_grooves`（按台阶对推环槽）产出的三个"孔"
   ——r5 于 176.18/214.18（实为 Ø40 两处肩面）、r6.476 于 238.68（实为螺纹
   牙顶线）——全是误报；v=220.569 只有一条线（Ø7 盲腔底），不存在对称的
   v=171.79 槽壁（那是 HATCH 环采样伪影）。**整个 `_step_grooves` 删除**
   （连同 STEP_SPAN_TOL / STEP_SYM_TOL / MIN_STEP），否则会发射三个伪孔。

## 新框架 src/rebuild/（v0.6.44，P1-D 跨 0/2π 缝拆分 + 微弧旋向——D79307-剖面基体 BRepCheck 转绿，2026-10-18）

**病根**：D79307-剖面的基体轮廓 84 段（34 弧）链闭合、无退化段，但
`BRepCheck_Analyzer` 报 `WIRE SelfIntersect×2 / FACE NotConnected×2`，发射器
抛 `OccBuildError: 特征 #0（base）建完后 B-rep 无效`。逐段核对
`ProfileSeg2` 的 `(sa, ea, ccw)` 后定位到 **4 条近整圆伪弧**：弦长
0.014~0.06mm，发射器按 `span = (ea-sa) mod 2π` 却读成 357.5°/359.9°，
把 0.013° 的微弧画成整圆、与相邻段自交。

**两条根因**（都在识别侧，不在发射器）：

1. `views/ring._split_primitives` 拆弧时 `ordered = [sa] + angs + [sa+span]`，
   其中 `angs` 是 `ang % TAU` 的**原始角**（∈[0, TAU)），而 `sa`/`sa+span`
   可能为负或超 TAU。原弧跨 0/2π 缝时（实测 `sa=-10.23°`），排序键正确
   但产出值会 `sa > ea`（实测 `sa=359.9871° > ea=0°`），破坏
   `_arc_prims` 的「ea = sa + span」契约。修成**先解缠到 `[sa, sa+span]`
   再排序**（并裁剪 `_angle_in_arc` 的 1e-4 端点容差）。
2. `features/recognizer._outline_ring_profile` 的弧旋向判据原用「弧中点弦
   叉积」：中点取圆上**精确**位置，端点却是环里**吸附后**的顶点。微弧
   矢高（~0.0003mm）小于顶点吸附误差（实测 0.0013mm）时，叉积符号由
   噪声决定——0.013° 微弧被翻成 359.987°。修成**映射行列式定全局翻面**：
   `fwd` 是轴置换 × 翻面、线性部分 det 恒为 ±1，环在视图系已归一为
   CCW 正面积 ⇒ 整幅环映射后统一保向或统一反向；逐段沿用环的 `ccw`
   （反向时取反），`sa`/`ea` 仍按映射后的端点重算。删除了原
   `|cross|<1e-9 ⇒ 旋向不可判` 的弃用出口（它会误杀真微弧）。

## 新框架 src/rebuild/（v0.6.26 待发，密集大图视图分离：YZYX 齿箱上盖首读，2026-10-12）

YZYX95.4-20 齿箱上盖（图幅 1830×1260、5 视图、52 条尺寸、齿箱类大件）是新框架
遇到的第一个**密集大图**。此前 9 个靶子全是间距宽松的小件，视图分离的全局比例
间隙（`max(8mm, 跨度×4%)`）从未暴露问题；YZYX 首跑把它暴露到底：**5 个视图粘成
1 个（1782×1260）、特征树 0 条**。本轮把三堵墙依次拆掉——视图分离/定性过关，
第四堵墙（特征识别）留给下一轮，另有一个环境陷阱顺手定位。

### ① 图框 + 家具把视图"焊"在一起（`views/view_detector.py`）

图框四条长边本身横跨全图，且与标题栏、对中符号、图幅分区标记连成一片 —— 它们
既是"连接线"又是"图元"，任何按间隙聚类都会被它们跨越空隙连起来。修法两条：

- **图框识别** `_frame_by_long_lines`：找构成矩形的长线（长度 ≥ `_FRAME_SIDE_FRAC`
  × 图幅跨度、贴合度 `_FRAME_TOL=0.5mm`）+ 框内至少 2 个视图尺寸的簇
  （`_FRAME_MIN_VIEW_ELEMS=8`）× 框外至少 3 个元素 ⇒ 判为图框；
  退化情形（图框不完整）走 `_frame_by_outer_edge` 兜底。
- **家具剔除** `_sheet_frame`：最多剥 3 层嵌套框；**不与图框矩形全包含**的元素
  全部归"家具"，出视图分离、记进 `Drawing.sheet_frame`（YZYX 实测 16 个 handle）
  以免以后有人以为读取器漏图元。

剥掉框后视图区跨度 1830→1182.1 宽 / 871.5 高，阈值随之从 gap_x0=71.28 /
gap_y0=50.40 降到 47.29 / 34.86 —— 阈值本身没改，是"跨度"变干净了。

### ② 两段式聚类结构性失效（同文件，新增 `_xy_cut` 递归切分）

旧流程是"先全局按 Y 切行、再在每行内按 X 切列"。YZYX 右列从上到下是「c 向」局部
视图（y 1194.3~1315.3）与下方大拱视图（y 896.1~1083.6），两者间空着 **110.7mm**
（阈值才 34.86）却在第一步被并进同一行：**左列俯视图的 y 跨度（857.3~1252.3）盖住
了这个区间**，全局按 Y 切时右列两视图与它同属一行。行内按 X 切时两者 x 完全重合
（同列）⇒ 永远切不开；y 信息在第一步已丢弃，后面再也找不回来。

改成**递归 XY 切分**：每块上先问"还有没有 y 向空隙"、再问 x 向，切不动即为一个
视图。每个子块重新做一次判断，故"被邻列遮挡的空隙"在子块里重新可见。YZYX 一次
得到 5 个视图，与图纸标题/手工读图**逐位对应**：

|---|---|---|---|
| V0 | (3265.4, 1541.2)-(3660.4, 1728.7) | 395×187.5 | left（备选 right，投影制未定） |
| V1 | (2478.3, 1541.2)-(2823.3, 1728.7) | 345×187.5 | **front**（layout:equal_extent） |
| V2 | (3337.4, 1194.3)-(3561.5, 1315.3) | 224.1×121 | section（标题「c   向」；scope=local） |

| V4 | (3265.4, 896.1)-(3660.4, 1083.6) | 395×187.5 | **未定性**（与 V1 既不同列也不同行） |

### ③ 2×N 布局的主视图判据失效（`views/view_typer.py`，三等定律裁决）

`_type_by_layout` 锚定主视图的判据是"**恰好一个**视图同时有行伙伴与列伙伴"——
这只对三视图 L 型布局成立。YZYX 是两列多行：五个视图**全都有行有列**，判据失效
⇒ 全表 UNKNOWN ⇒ 特征树 0 条。

补充依据取自投影本身的性质（GB 制图"三等定律"）：**真锚点的每个对齐伙伴都在共享
轴上与它等长**——列伙伴（竖直堆叠）同宽 = 长对正，行伙伴（左右并排）同高 = 高平齐。
`_extent_score` 满足 +1 / 违背 −1（相对 2% 与绝对 0.5mm 取大），取**唯一最大且 >0**，
否则返回 None 照旧报疑（不硬猜；正方形零件各视图全同尺寸时会并列，此时不裁决）。
YZYX 实测：V1 **+2**（列伙伴 V3 345 同宽、行伙伴 V0 187.5 同高）、V0 +1（V2 224.1
不等宽 ×）、V4/V3 −1、V2 −3 ⇒ V1 唯一最大 = 主视图，与手工读图一致（A—A 全剖即主
视图）。**特征树 0 → 22 条**。

### ④ 环境陷阱：MKL 的 LAPACK 延迟加载崩溃（不是代码问题，但卡死"必须出模型"）

`read_dxf` 读 YZYX 时在 cad-occt 里**静默杀进程**（`Windows fatal exception: code
0xc06d007f`，栈在 `ezdxf fit_points_to_cad_cv → np.linalg.solve`）。根因不在
ezdxf：cad-occt 的 numpy 走 MKL，**直接调 `$PY`（未经 `conda activate`）时
`envs/cad-occt/Library/bin` 不在 PATH**，MKL 的延迟加载 DLL（`mkl_rt.3.dll` 及其
子库）在**调用瞬间**才解析 ⇒ 解析失败 = 0xc06d007f 致命异常（无 faulthandler 时
连回溯都没有）。YZYX 是第一个含**拟合点 SPLINE** 的靶子（`8A9`/`8AC`/`8AD`：
ctrl=0、fit≠0），ezdxf 必须做插值拟合才会调 LAPACK —— 之前所有 cad-occt 跑法都没
碰过 linalg，所以从未暴露。用法：`PATH=<env>/Library/bin:$PATH $PY …`（已写进
CLAUDE.md）。

### SW 基体拉伸破冰（同日的发射器修复，`emit/sw_builder._sketch_profile`）

症状：bracket 基体在 SW 里 **`FeatureExtrusion2` 返回 None**（OCC 侧早已成功），
122 段带弧轮廓拉伸全败。bisect 探针（`_probe_sw_arc_bisect.py`，40+ 变体）
定出**两个独立触发因**，并各配一条修复：

1. **碎片线链**：SW 草图求解器拒绝"30+ 段首尾相接的碎片微线段链"——同一 U 形槽

   122 实体（未合并）连**纯折线环**都拉不出来（`chords` 变体实测失败）。

   解析面积逐位相同 8347.756mm²；122→62 实体）。
2. **顺时针劣弧的调用形态**：四点实验（r10 角区，正确短弧 214.602 / 补弧 3356.194）
   + bisect 定死 SW 的 `CreateArc` 语义**与文档不符**：`direction=True` 实测 =
   **顺时针**；`direction=False` 实测 = **取劣弧**（CCW 走优弧时会把劣弧画出来——
   cwF 反例）。bracket 两条 r3 顺时针劣弧按"几何正确"传 True 会**静默拒绝拉伸**，
   传 False 通过且几何正确（`mx119flip`/`mxfo2` 实测）。修复 = **span ≤ π 的弧
   一律传 False**；优弧用"顺时针 + 正确端点序"表达（换序走顺时针 = 同一条优弧）。
   旧 `cross<0` 判据只保留在优弧分支。
