# 通用性盲测报告（P0，2026-10-17）

> **目的**：回答一个此前没有被量化的问题——`src/rebuild/` 是不是只会做已参与
> 开发的靶子（6 简单件 / bracket / PF60K / YZYX）？方法是用 **held-out 件**
> 跑默认管线（gate 生效），记录读懂程度与 force 硬推偏差，**不依据结果调代码**。
>
> **口径**：本表是诊断仪，不判红绿。`gate=blocked` 是框架按设计拒绝发射
> （正确行为）；最危险的是 `gate=pass` 但体积/bbox 大偏——记为**静默错误**。
>
> **局限**：4 个零件都是 `model_to_drawing.py` 的闭环出图（与管线同源），
> 不是第三方图纸；样本量小。它们只能检验"换零件几何是否还读得动"，不能
> 代替真实图纸。HLR 评分未纳入——现有 `yz_hlr.py` 是 YZYX 专用常量，通用
> 投影评分需另建。

## 2. 关键结论

1. **视图分离本身没问题**。抽检 D79307 / IMU / 轴测量三张图，各分出 3 个视图，
   类型（V0 top / V1 front / V2 left）与版面位置全部正确。失败发生在**视图之后**
   的轮廓/尺寸/坐标层，不是"图都分不开"。
2. **轴向位置绑定缺失是跨靶子的系统性问题**。7 个用例里所有需要轴向定位的
   孔/凸台都打了同一条日志：`没有 axial_at ⇒ 沿轴按 0 起（默认值，非图纸读数）`。
   这正是 `CLAUDE.md` 已记账的静默默认；P0 证明它在 held-out 件上是精度主因。
3. **基体轮廓通道不鲁棒**，三种不同表现：
   - D79307：`no_ring_found` → 基体退化为 `projection:view_bounds` 的
     40.01×35.00 矩形（轮廓内的台阶/缺口全丢），force +540.8%；
   - spoon：环覆盖 `coverage(0.27×0.50) < 0.75` → 同样退化为包围盒；
   - 轴测量：环**读到了**，但选错了视图——基体 profile 取自俯视图 V0
     （origin y=116 正是 V0 下边界），沿 x 拉伸 40，得到 bbox +20/+116；
     正确做法是取侧视图/主视图作拉伸轮廓。
4. **gate 还不能识别"读错视图"**。D79307 / spoon 走包围盒回退时会报
   `特征歧义未消解`（正确）；轴测量拿到了一个环（哪怕视图选错），gate 就
   认为没有疑问。IMU 的轴向缺省同样不触发任何疑问。结果就是 3/4 个
   `gate=pass` 是静默错误。
5. **这些不是信息论不可解**。旧管线在同一批件上的成绩：D79307 −0.001%、
   轴测量 100% 覆盖、IMU/D79307 均有闭环出图基线。差距在基本层（视图→
   轮廓→尺寸→坐标），不在"图纸缺信息"。

## 4. 对下一步的影响（P1 优先级建议）

按"影响面 × 通用性"排序，而不是按 YZYX 的 HLR 分数：

1. **轴向位置绑定（`axial_at`）**——影响 7/7 用例，是通用尺寸绑定问题。
   从视图对应/剖面 HATCH/标注读轴向位置；缺失时保持拒绝或显式降级，
   不再默默按 0 起。
2. **基体轮廓的视图选择 + 环提取鲁棒性**——轴测量选错俯视图；D79307
   `no_ring_found`；spoon 覆盖率门控。按"长对正/高平齐"与拉伸方向选视图；
   T 结点/多环/T 型拆分点的环提取要加强；包围盒回退必须继续 block。
3. **gate 扩展**——把"基体走包围盒回退 / 轴向缺省 / 轮廓覆盖率低 / 视图
   与拉伸方向不自洽"纳入 blocking 或置信度降级，消灭静默错误。P0 证明
   当前的 `blocking()=0` 在 held-out 件上不可信。
4. **发射器 B-rep 卫生**——D79307-剖面基体 BRepCheck 无效，属通用发射器问题。
5. **YZYX 剩余三处**（东端假料 / Ø100 圆底 / 塔顶斜线）降为 P2：它们是
   词汇缺口，先修上面的基本层。东端假料尤其应先按"多视图剪影共识"做成
   通用规则，而不是 YZYX 专用补丁。

## 9. P1-D 落地复测（v0.6.44，2026-10-18）

**改动**：修 D79307-剖面基体的 `BRepCheck` 无效，根因**不在发射器**，在识别
侧两处：

1. `views/ring._split_primitives`：拆弧角度混用了两种口径——`angs` 是
   `ang % TAU` 的原始值，`sa`/`sa+span` 可能为负或超 TAU。跨 0/2π 缝的弧
   （实测 `sa=-10.23°`）会拆出 `sa > ea` 的段（`sa=359.9871° > ea=0°`），
   破坏 `_arc_prims` 的「ea = sa + span」契约。修成先解缠到
   `[sa, sa+span]` 再排序。
2. `features/recognizer._outline_ring_profile`：弧旋向原用「弧中点弦叉积」，
   中点在圆上精确、端点却是**吸附后**顶点——微弧矢高（0.0003mm）小于
   吸附误差（0.0013mm）时符号由噪声决定。修成**映射行列式**定全局翻面
   （`fwd` = 轴置换 × 翻面，det 恒 ±1），逐段沿用环的 `ccw`。

**实测**：D79307-剖面基体 `[OK] #0 base 拉伸 84 段轮廓（34 弧）`——原
`OccBuildError ... BRepCheck_Analyzer 判定 B-rep 无效` 消失。该用例仍
`BLOCKED`，但拦路换成了两条**特征歧义**（`#4.radius` 12.4 vs 标准 12、
`#5.radius` 4.1 vs 标准 4），不再是发射器崩溃；force 体积 +21.67% 与
三视图 +20.71% 同属"尺寸对、内容错"。
